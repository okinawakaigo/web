# ダッシュボードのデザイン

会社全体の業務を管理する担当者が、届いた相談を確認し、次に必要な対応に進むための画面。アプリ名は `dashboard`、初期の業務領域は採用。

## 設計方針

- 色：Paper `#ffffff`（作業面）、Canvas `#f5f8f7`（背景）、Sidebar `#eaf1ee`（会社のナビゲーション）、Ink `#203e3a`（文字）、Primary `#136c60`（操作）、Warning `#805b1f`（未対応）。実体は共通UIのtokens.css。
- 文字：Noto Sans JPを見出しと操作に、DM Sansを数字に使用。見出し28px、本文14〜16px、補足12〜13px。左揃えで一覧性を優先。
- 配置：240pxの固定サイドバーと、広い作業面。概要は対応状況と新着、採用は検索可能な一覧。詳細は右から開くパネル。モバイルは開閉式ナビゲーションと全画面の詳細。
- 特徴：会社の淡いグリーンをナビゲーションに集め、作業面は静かに保つ。未対応を優先して見つけられる。実装前の業務をダミーのメニューとして並べない。

```text
会社 / Dashboard    │ 概要
                    │ 状況説明              更新
概要                │ 採用の対応状況（実数）
                    │
採用                │ 最近の参加相談
  参加相談          │ 名前 / 仕事 / 状況 / 受付日
                    │
採用サイトを開く    │ 選択時に右側へ詳細を表示
```

初案の大きな指標カードの反復を見直し、採用の対応状況を一つのまとまりで表示。採用サイトの明朝・コピー主体の構成は引き継がず、共通の色・操作部品を使って業務に適した密度を設定する。

## 操作と拡張

一覧の検索はサーバー側で名前・仕事を対象に実施。状態別件数は全件から集計し、検索結果件数と区別する。詳細は項目の確認、対応状況と担当者メモ、通知状況に分ける。未保存の変更がある状態での移動・再読み込みは確認する。

業務領域を増やす場合はサイドバーの領域と対応する画面を追加する。全体のシェル、共通トークン、APIの認証境界を共用する。このガイドは開発資料であり、公開アプリには含めない。
