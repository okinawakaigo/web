# ダッシュボードのデザイン

会社全体の業務を管理する担当者が、届いた相談を確認し、次に必要な対応に進むための画面。アプリ名は `dashboard`、初期の業務領域は採用。

## 設計方針

- 色：Paper `#ffffff`（作業面）、Canvas `#f5f8f7`（背景）、Sidebar `#eaf1ee`（会社のナビゲーション）、Ink `#203e3a`（文字）、Primary `#136c60`（操作）、Warning `#805b1f` / `#fbf1d9`（未対応）。実体は共通UIのtokens.css。暖色は未対応の見出しとサイドバーの件数だけに使い、他は緑灰でそろえる。
- 文字：Noto Sans JPを見出しと操作に、DM Sansを件数に使用。見出し28px、本文14px、補足12〜13px。左揃えで一覧性を優先。
- 配置：232pxの固定サイドバーと、広い作業面。上部バーとフッターは置かず、ページ見出しの右に最終更新と更新ボタンを置く。詳細は右から開くパネル。モバイルは細い上部バー（メニューと会社名）、開閉式ナビゲーション、全画面の詳細。
- 特徴：会社の淡いグリーンをナビゲーションに集め、作業面は静かに保つ。矢印・頭文字アイコン・行末のシェブロンは置かず、罫線と並び順で構造を伝える。実装前の業務をダミーのメニューとして並べない。

## 概要（対応ボード）

概要は指標カードではなく、対応の流れの順に並べた3つのレーン（未対応・連絡済み・日程確定）で、実際の相談を名前で表示する。件数は全件の集計、各レーンには受付が新しい順に最大5件。件数が表示件数より多いときは「すべて見る（他N件）」で絞り込み済みの一覧へ移動する。対応完了は下段の件数だけで、累計と並べる。

```text
沖縄介護センター    │ 概要                       最終更新 21:40  更新
ダッシュボード       │ ┌ 未対応      4 ┬ 連絡済み    2 ┬ 日程確定    2 ┐
                    │ │ 比嘉 美咲 3時間前│ 新垣 さくら 昨日│ 宮城 健  2日前 │
概要                │ │   ヘルパー     │   相談員       │   ヘルパー     │
採用                │ │ …              │ …              │ …              │
  参加相談  4       │ │ 未対応をすべて見る│ 連絡済みをすべて見る│ 日程確定をすべて見る│
                    │ └ 対応完了 3件                           累計 11件 ┘
採用サイトを開く    │
```

## 参加相談（一覧と詳細）

- 一覧：検索欄と対応状況の絞り込み（件数付き）を同じ列に置き、表はお名前・気になっている仕事・対応状況・受付（相対時刻、正確な日時はツールチップ）・担当者への通知。通知は受付成功のときは空欄にし、例外だけを表示する。
- 詳細：相談者の名前を見出しにし、対応状況と受付日時を添える。広い画面では左に送信履歴と返信入力欄、右に相談内容・対応状況・担当者メモを配置。返信はメールとして送信し、社内メモは相談者に送信しない。900px未満では「返信・送信履歴」「相談内容・メモ」を切り替える。

```text
相談者名 / 対応状況 / 受付日時                          閉じる
─────────────────────────────────────────────────────────────
返信・送信履歴                     │ 相談内容
  フォームで届いた相談             │ 仕事・年齢層・性別
                担当者からの返信   │ 都合のよい日時・聞きたいこと
                送信受付済み       │
───────────────────────────────────│ 対応状況・担当者メモ
宛先 / 件名 / 返信本文              │
                    メールを送信   │ 対応状況を保存
```

返信では既存の緑灰色と共通の入力部品を使う。SNSの会話画面のように時系列で確認できる構成を参考に、相談フォームとメールの送信履歴を表示する。添付や受信済みメールを模したダミーは置かない。返信の主操作と社内の記録保存は領域を分け、ローカルでは「テスト返信を記録」と明示する。送信失敗・結果不明・送信受付済みを区別し、API受付を配信完了として表示しない。

## 操作と拡張

一覧の検索はサーバー側で名前・仕事を対象に実施。状態別件数は全件から集計し、検索結果件数と区別する。概要のレーンは未絞り込みの1ページ目（50件）から状態ごとに抜き出すため、古い相談は「すべて見る」から確認する。未保存の変更がある状態での移動・再読み込みは確認する。

一覧に相談内容の抜粋を出す場合は、`ConsultationSummary` に要約項目を追加し、APIの `SELECT` を合わせる。業務領域を増やす場合はサイドバーの領域と対応する画面を追加する。全体のシェル、共通トークン、APIの認証境界を共用する。このガイドは開発資料であり、公開アプリには含めない。
